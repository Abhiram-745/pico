# Halo Tools / Connections

This integration is local Halo bridge code using the official `@composio/core` SDK. It is separate from Grok Bot MCP and from any assistant's own connectors.

## Enable

1. Install dependencies with `npm install` on a machine with npm registry access, then run `npm run ui`. Offline SDK tests and the UI build pass locally; live account behavior requires configured credentials.
2. Get a project API key from the [Composio developer dashboard](https://platform.composio.dev/). This is a Composio project key, never a Gmail password or a Google API key pretending to authorize mailbox access.
3. Start Halo locally and open Settings → Tools / Connections. Save the key using the password field. On Windows this uses a Generic Credential named `Halo/Composio` in Windows Credential Manager. Persistent saving on other platforms is deliberately unavailable; a process-injected `COMPOSIO_API_KEY` is supported. No key is saved in Halo's JSON settings or environment files.
4. Enable Composio. Use a stable local user ID, initially `halo-local`. For reuse, it must match the user ID in the same Composio developer project. Changing it clears account selections.
5. Existing active private accounts appear without fresh OAuth. Select the desired Gmail/Outlook/calendar account explicitly. If none exists, click Connect, then Continue authorization. A managed SDK session generates the hosted HTTPS consent link. No custom auth config ID or additional OAuth feature flag is required. Return to Halo; status refreshes every 15 seconds. Refresh is also available manually. Links can expire; retry Connect after expiration.
6. Select the newly active account and enable its Watch checkbox. Desktop mode must also be on. Remote watch collection is throttled to once a minute and is triggered by desktop polling (default 15 seconds, configurable 5–120 seconds). Expect roughly 60 seconds plus a desktop polling interval between remote observations, plus provider latency. Provider waits are bounded to 6 seconds; desktop source waits to 8 seconds. Both switches are off by default. Disabling the feature prevents subsequent integration calls.

Config is stored in `composio.json` under Halo's local data directory (`%LOCALAPPDATA%\Halo`, or `HALO_HOME`). It contains enabled state, user ID, watch app names and selected account IDs, never keys or OAuth tokens. Do not edit credential files to configure Halo.

## What is wired

- Sessions are restricted to `gmail`, `outlook`, `googlecalendar`, `slack`; their tool filters enable only the specified read/draft slugs, and disable sandbox code execution. The session object/MCP credentials never go to the browser or model.
- Explicit Connect uses `session.authorize(toolkit)` only if there is no active same-user account to reuse. Connection status uses filtered SDK listing. Disconnect disables the selected same-user connection through Composio; it does not delete the provider account. Other apps sharing that connection may lose access. Reconnecting an inactive account requires fresh authorization.
- Account selection is explicit for tool/watch execution. Shared/team connections are excluded. Explicit pin plus verified ACL session access is not implemented; do not assume a team connection grants this local user access.
- Gmail unread cards show the size of a bounded sample (up to 10), not total unread. Inbox items also produce a **may need reply** card, a review heuristic rather than an AI claim that a reply is needed. Watch cards may show a bounded, credential-filtered sampled subject, never a message body. Samples identify changes; unread does not mean newly delivered.
- Google Calendar cards count timed primary-calendar events starting within 30 minutes. All-day events are excluded. Poll arguments are selected from the current official tool schema; an incompatible schema produces no card. Open/Dismiss use existing desktop controls; Open goes only to fixed Gmail/Outlook/Calendar provider home pages, not content-supplied links. Select the intended account in the provider browser if several are signed in.
- Outlook linking/status/account selection work at the SDK boundary. Outlook unread inbox watching uses `OUTLOOK_QUERY_EMAILS` with `filter: 'isRead eq false'`, `folder: 'inbox'`, `top: 10`, `select: ['id', 'subject', 'isRead', 'receivedDateTime', 'lastModifiedDateTime']`, `orderby: 'receivedDateTime desc'`, and `user_id: 'me'`. The adapter validates these fields/types against the advertised pinned tool schema and surfaces unavailable if incompatible. It never substitutes a `query` field. See the [official Outlook toolkit schema](https://docs.composio.dev/toolkits/outlook.md). Slack supports linking/status only, with no watch or execution slugs.
- The desktop driver's model tools include `search_mail`, `list_unread`, and `draft_reply_do_not_send` while enabled. `HostAgent` routes them through `assessComposio` and an explicit Halo approval card; `autoApproveAll` does not bypass this gate. The selected Gmail account is used. Draft arguments must match the official Gmail draft schema. These are available in desktop action turns, not the ordinary chat-only response path.
- No generic HTTP executor, proxy, MCP multi-executor, or send model tool is exposed. The exact send slugs are backend-gated by an expiring, single-use receipt bound to tool, arguments and account. There is intentionally no user-facing receipt-minting/send workflow in this pass: sends remain inaccessible to agent tools. No live sends were performed.

## SDK findings and alternatives

[Sessions reference](https://docs.composio.dev/reference/sdk-reference/typescript/sessions) and [session authorization](https://docs.composio.dev/reference/sdk-reference/typescript/session) document creating a session for a user and obtaining a hosted consent redirect. [Account selection](https://docs.composio.dev/docs/configuring-sessions) supports explicit account pins; Halo uses arrays in its session configuration and checks active private account membership before session creation.

For direct OAuth integrations, managed `connectedAccounts.initiate` was retired in the 2026 migration; use [`connectedAccounts.link`](https://docs.composio.dev/reference/sdk-reference/typescript/connected-accounts). Halo uses session authorization instead of requiring custom auth IDs. Direct execution uses [`tools.getRawComposioToolBySlug` and `tools.execute`](https://docs.composio.dev/reference/sdk-reference/typescript/tools), caching the returned concrete version and rejecting missing/`latest` versions. It never uses `dangerouslySkipVersionCheck`.

The least repetitive path is reuse of an existing same-project/same-user account. Browser consent is normally one-time until revoked/expired or scopes change. Gmail/Calendar device OAuth is not a supported substitute for these scopes; no Slack device flow is implemented or claimed. Slack can use managed hosted consent; workspace/admin approval may be needed. No Slack actions have been added.

For **Claude Desktop**, Composio documents a separate custom connector at `https://connect.composio.dev/mcp`. For **Codex/Claude Code**, the [Composio Connect guide](https://docs.composio.dev/docs/composio-connect) recommends its native CLI/plugin unless MCP is explicitly desired. These are documentation-only options here: no CLI login, credential lookup, plugin installation or assistant reconfiguration was performed. [Consumer and developer project boundaries](https://docs.composio.dev/kb/guide/consumer-project-boundaries-and-auth-selection) mean those assistant connections are not automatically available to Halo. Never scrape cookies, browser sessions or assistant credential stores to bridge the gap. Halo does not invoke remote coding agents or remote workbench tools.

## Windows verification checklist

- With dependencies installed, run `npm run check:composio`, `npm run check:desktop`, `npm run ui`.
- Start Halo with no injected key and feature disabled: tools should stay disabled without errors/network calls. Enable without a stored key: status should show no key and no connections.
- Save a new project key in Settings. Check that **Windows Credential Manager → Windows Credentials → Generic Credentials** lists `Halo/Composio`; do not reveal/copy its secret. Restart Halo and enable Tools to verify runtime retrieval. No environment-file edit is needed.
- Confirm Settings and key routes reject nonlocal/cross-origin requests. The UI never displays a key.
- Reuse a private same-user account, select it, and verify that Connect does not demand repeated consent. For a new account explicitly click Connect and complete consent, then wait for ACTIVE. This OAuth flow has not been tested end to end in the coding environment.
- Enable Gmail/Outlook/Calendar watch and Desktop mode; check unread/sample wording, possible-reply wording and upcoming timed event counts. Open should open the fixed provider page. Dismiss should suppress the same card until its content changes. Watch cards use no message-body AI summarization.
- Exercise a read or draft tool using mock data first; decline the Halo approval and verify no action occurs. Enable autoApproveAll and confirm the integration approval still waits. Do not test live sending without a separately reviewed send UI/workflow.
- Explicitly disconnect only a test connection you intend to disable; confirm its status changes and watch stops. No live disconnect was done in this task.

Read-only live check: `node scripts/verify-composio-live.mjs`. It checks only the inherited process variable and lists counts/statuses; it never loads dotenv or reads the OS key store. Optional `HALO_COMPOSIO_USER_ID` selects the user for this script. Runtime may access its own Credential Manager secret, but the verification script never extracts it.

Watch timestamps distinguish `changedAt`/`lastActivity` (last meaningful content change) from `observedAt`/`updatedAt` (latest successful sample). Repeated unread samples do not outrank newer changes. Provider failures, including connection-list failures, display unavailable rather than unread. Watch changes synchronously cancel briefings and remove deselected Composio results, including while paused; late polls cannot restore revoked signals.

WhatsApp is a separate opt-in local window-title watch, not a Composio inbox adapter. On Windows, visible Desktop/Web titles may expose unread badges; hidden tabs, tray-only windows and differing title formats may expose nothing. No message content or same-count replacement can be inferred. Repository research found no definition of Instinct; no Instinct product integration is claimed. See [Instinct/WhatsApp setup and limitations](instinct-whatsapp.md). Remote email watching is polling (roughly 60 seconds plus the desktop interval and provider latency), not push delivery. Provider faults show unavailable, not an all-clear watch status.
