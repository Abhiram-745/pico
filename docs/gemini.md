# Gemini: window watching and optional model provider

These are separate choices. Neither signs in, starts OAuth, reads Gemini chat history, or connects an account automatically.

**Watch Gemini** in Settings → Watching, Workspace preferences, or island watching preferences observes an already-open Gemini web/PWA window exposed by Windows. It needs no API key. Halo matches the observed window using the rules below; this does not claim Google ships a native Windows Gemini app. A plain open window stays “Open”. Only enabled generation/approval buttons or explicit completion/failure status controls infer a more specific state. Generic chat text, editable fields and disabled/password controls cannot provide Gemini progress evidence. Gemini has no transcript/database adapter. Unsupported/localized titles and controls can remain unknown; hidden tabs/tray windows may expose nothing. No Gemini content is passed to an AI briefing from this adapter.

Matching is local and conservative. Browser processes `chrome`, `msedge`, `brave`, and `firefox` (optional `.exe`, case insensitive) accept exact `Gemini` / `Google Gemini`, those product names followed by a spaced `-`, `–`, `—`, or `|` and a chat title, or chat titles ending in a spaced separator plus `Google Gemini`. Optional browser suffixes are Google Chrome, Microsoft Edge, Brave / Brave Browser, Firefox / Mozilla Firefox. URL titles must start with the exact host `gemini.google.com`, optionally `http://` or `https://` and a slash path. PWA windows use the same browser/title rules without needing a browser suffix. Desktop process names are limited to `gemini`, `geminisetup`, `geminidesktop`, or `geminiapp`, optionally `.exe`. This observes app/session presence; it cannot verify the Google account or sign-in. Comparing Gemini models, Ask Gemini - Gmail, news mentions, unrelated processes and lookalike URL hosts are rejected.

Progress comes only from enabled, non-password Button / StatusBar / ProgressBar controls. A Button named `Stop` or explicit generation controls such as `Stop generating` / `Stop response` means working; approval controls mean waiting; explicit completion/failure statuses mean completed/failed. Text/Edit content never supplies progress. Chrome and Gemini selections use separate evidence caches.

Normal app tiles use the existing fallback; no Gemini logo/art was added. The known opening target is the fixed `https://gemini.google.com/` URL. Existing installed-app/PWA versus website choice rules still apply. Opening a watched result only focuses an unambiguous current window after a user gesture; it does not log in or generate a reply.

**Optional: use Gemini API for Halo’s own replies/actions** is the separate provider choice in installed Settings. Save a key with the password field and **Save key securely**. On Windows this writes Generic Credential `Halo/Gemini` in Windows Credential Manager and refreshes the selected Gemini provider immediately while Halo is idle. Alternatively set process environment `GEMINI_API_KEY` before starting Halo (also supported on non-Windows); environment takes precedence over the credential. Persistent saving on non-Windows requires Windows Credential Manager and is unavailable there. Then select Google Gemini API, or configure `PICO_PROVIDER=gemini` before the next start. A key alone does not select Gemini. Availability is not verification of access or quota; saving makes no API call. Keys never enter Halo JSON settings, repo `.env`, browser storage, responses or command arguments; the credential writer receives the key on stdin. Only provider/model preferences are saved in `model-provider.json`. Selecting Gemini without a key detaches the LLM with no other-provider fallback. Watch Gemini stays separate and needs no key.

Every Gemini tier defaults to **`gemini-3.5-flash-lite`**, the current cheap/fast recommendation verified November 5, 2026. **`gemini-3.8-flash`** is the explicit higher-quality option. `GEMINI_MODEL` can choose either; valid Gemini `PICO_MODEL` / `PICO_MODEL_<TIER>` overrides also work for environment-based selection. The saved Settings model applies to every Gemini tier. Other model IDs, retired 2.0 defaults, restricted 2.5 defaults, arbitrary Pro models, custom endpoints, gateway routing and cross-provider fallback are not used on the Gemini path. Existing OpenAI mini/nano allowlist and other providers' fallback behavior are unchanged. If selected without a key, Gemini stays unavailable instead of silently using an OpenAI/other key. Switching provider is rejected while Halo has an active task/reply/voice/approval; it does not interrupt that work. Optional desktop AI briefings remain **direct OpenAI only** and require their own configuration.

Gemini reuses the existing OpenAI-shaped client with `responses: false`:

- Base: `https://generativelanguage.googleapis.com/v1beta/openai/`; chat and tool calls use `chat/completions`, model discovery uses `models`.
- Authentication: `Authorization: Bearer GEMINI_API_KEY`. No key in a URL and no native Gemini `x-goog-api-key` header.
- Requests use Chat Completions `messages`, `max_tokens`, SSE streaming, function tools and `image_url` data URLs for screenshots. Gemini requests ask for `reasoning_effort: minimal`; Gemini 3 thinking is not claimed to be disabled. OpenAI-only Responses/image-detail/parallel-tool options are omitted. Only one valid named tool call is returned as actionable; malformed, unknown or multiple calls return no action.
- Cancellation stops blocked SSE readers and rejects late JSON results; provider errors redact the configured key. Provider selection itself constructs configuration only and makes no API/auth/probe call. The bridge's normal startup model-list check may run only for a selected, keyed provider; no completion is used as a configuration probe.

Window watching uses the existing local adaptive cadence: saved baseline B=5–120s (default 15), three 5s checks after changed evidence, then three B intervals, then min(2B,120s) while unchanged. Local source failures use min(B×2^n,120s), starting at n=1. Quiet affects interruptions, not polling. Email's independent per-account cadence and monotonic HTTP/WebSocket snapshot acceptance are unchanged; see [exact timing and limitations](instinct-whatsapp.md#exact-adaptive-timing-and-limits). Unchanged Gemini controls preserve meaningful change time rather than repeatedly outranking new email. Foreground voice/agent/approval retains island priority.

Offline validation: `npm run check:gemini`, `npm run check:providers`, `npm run check:workspace`, `npm run check:composio`, `npm run check:desktop`, intent/agent-speed/app tests, and `npm run ui`. Fixtures inject environment values, SDK/HTTP responses, clocks and timers. No actual key, account, paid completion or Windows sign-in was tested. Gemini key validity, project availability/quota, live model/payload compatibility, real Windows/PWA titles and accessibility exposure still need caller-controlled validation. SDK compatibility docs describe a supported shape, not a guarantee every live model exposes identical behavior.

Official references (public notes supplied and verified November 5, 2026): [OpenAI compatibility](https://ai.google.dev/gemini-api/docs/openai), [current models](https://ai.google.dev/gemini-api/docs/models), [deprecations](https://ai.google.dev/gemini-api/docs/deprecations), [API keys](https://ai.google.dev/gemini-api/docs/api-key).
